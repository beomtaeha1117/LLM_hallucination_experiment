# 실험 B — 동일 지시의 입력 내 위치 효과

확정일 2026-09-08. 이 문서가 실험 B의 기준이다. 코드와 어긋나면 코드를 고친다.

실험 A(내용 효과, P0~P3 + 비교군)와 **문항도 과제도 다르다.** 결과를 합쳐 해석하지 않는다.

---

## 0. 연구질문

**같은 문구의 보류 지시를, 입력의 어느 자리에 넣느냐에 따라 환각률·과잉보류가 달라지는가.**

방향 가설을 세우지 않는다. "앞에 넣으면 잘 듣는다"를 전제하지 않으며, **위치 효과가 없다는 결과도 그대로 보고한다.**

선행연구는 배경으로만 쓴다. `Lost in the Middle`(Liu et al., TACL 2024)은 **긴 문맥 안 정보의 위치**에 관한 것이지
지시문의 위치가 아니다. `Order Matters`(arXiv:2502.17204)는 다중 제약 지시의 순서를 다룬다.
둘 다 **한국어 환각 억제 지시의 위치 효과를 검증한 것이 아니다.** 이 점을 이론적 배경에 명시한다.

---

## 1. 조건 — 3 + 1

지시 문구·지문 내용·지문 순서·질문·출력 형식은 **전 조건 동일**. 바뀌는 것은 지시의 자리뿐이다.

| 조건 | 입력 순서 | 역할 |
|---|---|---|
| `FRONT` | 지시 → 자료1 → 자료2 → 질문 | 주분석 |
| `MID` | 자료1 → 지시 → 자료2 → 질문 | 주분석 |
| `BACK` | 자료1 → 자료2 → 지시 → 질문 | 주분석 **(참조수준)** |
| `NOINSTR` | 자료1 → 자료2 → 질문 | 별도 참조점 |

**`NOINSTR`은 네 번째 수준이 아니다.** 이 조건만 지시가 없으므로 길이도 다르다.
`NOINSTR`을 위치 요인에 넣으면 **"지시의 유무"와 "지시의 위치"가 한 축에 섞인다.**
따라서 위치 효과의 검정은 `FRONT`/`MID`/`BACK` 3수준끼리만 하고, `NOINSTR`은 사전 계획 대조로 따로 본다.

**참조수준을 `BACK`으로 두는 이유**: `FRONT`를 기준으로 잡으면 "앞이 정상, 나머지가 이탈"이라는 틀이
분석 단계에서부터 깔린다. 질문에 가장 가까운 자리를 기준으로 두고 앞·중간이 거기서 벗어나는지를 본다.

### 구현 규칙 (어기면 실험이 무효)
- 지시는 **같은 user 메시지 안에서만** 이동한다. `FRONT`만 system 메시지에 넣지 않는다.
- system 프롬프트는 4조건 모두 **`P0_baseline`으로 동일**. 조작하는 지시는 오직 user 메시지 안에 있다.
- 질문은 **항상 마지막**이다. `BACK`의 '뒤'는 지문 뒤·질문 앞이지, 메시지의 절대 끝이 아니다.
- 지문과 지시를 마커로 명확히 가른다. **`MID` 지시가 자료의 일부로 읽히면 안 된다.**

```
<자료 1>
{doc_a}
</자료 1>

[지시]
{instruction}
[/지시]

<자료 2>
{doc_b}
</자료 2>

[질문]
{question}
```

## 2. 지시 문구 — 사전 선정, 고정 1개

```
제공된 자료에 답할 근거가 있으면 답하십시오. 근거가 부족하면 추측하지 말고
"제공된 자료만으로는 확인할 수 없습니다"라고 답하십시오.
```

- `instruction_id: B-INSTR-01`. 실험 기간 중 **변경하지 않는다.**
- **본실험 결과가 좋게 나온 문구를 고르지 않는다.** 문구가 작동하는지는 **개발용 문항 5개**로만 확인하고,
  그 5개는 본실험 40문항에 **넣지 않는다**(`data/questions_b_dev.csv`로 분리).
- 실험 A의 `P1`과 문구를 통일하지 않는다. A는 세계지식 기반 보류, B는 **제공 자료 기반 보류**로 과제가 다르다.

---

## 3. 문항 — 40개, 전부 신규 작성

기존 `context_qa` 20개는 **쓰지 않는다.** 지문 평균 139자로, 앞·중간·뒤가 사실상 같은 자리다.

| 구분 | 수 | 근거 위치 | 비고 |
|---|---:|---|---|
| answerable | 10 | 자료 1 안 | |
| answerable | 10 | 자료 2 안 | |
| unanswerable — 없는 수치 | 10 | 없음 | 자료가 다루는 주제이나 그 수치는 없음 |
| unanswerable — 없는 개체/인물 | 10 | 없음 | 자료에 등장하지 않는 대상 |
| **합계** | **40** | | |

### 3.1 지문은 허구 세계로 쓴다 — B가 A보다 싼 이유
자료는 가공의 도시·기관·제도로 작성한다(A시, 남해권 광역교통조합 등).

- 정답 근거가 **지문 안에** 있으므로 KCI·RISS·법령 조회가 **필요 없다.** A의 135건짜리 검증 병목이 B에는 없다.
- 모델이 **세계지식으로 우회 답변할 수 없다.** "지문에 없다"가 확실해진다.
- 검증 항목은 지문 자체의 내적 일관성뿐이다(같은 수치가 두 번 다르게 나오지 않는지).

### 3.2 지문 길이 통제
- 자료 1, 자료 2 각각 **한국어 420~480자**, 합계 약 900자. 두 자료의 글자 수 차이 **±10% 이내.**
- 짧으면 위치가 구분되지 않고, 길면 960응답의 생성 시간이 급증한다. 그 사이를 택했다.
- 작성 기준은 글자 수지만, **토큰 수는 모델별로 다르므로 응답 행에 기록한다**(§5).
- 문단 수를 3문단으로 통일한다. 근거 문장이 문단 경계에 걸리지 않게 한다.

### 3.3 정답 근거 위치 기록
`evidence_doc`(1 또는 2)뿐 아니라, 해당 자료 안에서 근거 문장이 시작하는 **문자 오프셋**과
**몇 번째 문단인지**를 문항 CSV에 적는다. 위치 효과가 근거 위치와 얽히는지 사후에 볼 수 있어야 한다.

`answerable` 20개에서 근거를 자료1/자료2에 **10:10으로 균형 배치**한다. 이게 깨지면
"지시 위치 효과"로 보고한 것 안에 "근거 위치 효과"가 섞인다.

## 4. 규모

**40문항 × 4조건 × 3반복 × 2모델 = 960응답.**

- 모델: 실험 A의 주모델·재현모델 2종(3번째 모델은 넣지 않는다).
- 반복 3회, **temperature 0.7 고정, seed만 1/2/3**. 실험 A와 같은 규칙.
- 같은 문항의 반복 응답을 독립 문항으로 취급하지 않는다(문항 ID로 클러스터).

**검정력은 넉넉하지 않다.** 40문항은 탐색적 규모다. p값만 보고하지 말고
**효과크기와 신뢰구간을 함께** 보고하고, 결론에 "탐색적"이라고 쓴다.

---

## 5. 응답 행에 반드시 기록할 것

기존 `RAW_COLUMNS`에 더한다. **prompt 내용과 position은 별개 변수로 관리한다.**

| 컬럼 | 내용 |
|---|---|
| `position` | `FRONT` / `MID` / `BACK` / `NOINSTR` |
| `instruction_id` | `B-INSTR-01` (내용 식별자 — position과 분리) |
| `evidence_doc` | `1` / `2` / `none` |
| `evidence_char_offset` | 해당 자료 내 근거 시작 문자 위치 |
| `doc_a_chars`, `doc_b_chars` | 지문 길이 통제 확인용 |
| `instr_token_index` | 실제 프롬프트에서 지시가 시작하는 **토큰 인덱스** |
| `prompt_tokens` | 전체 프롬프트 토큰 수 (기존 컬럼 재사용) |

`instr_token_index / prompt_tokens`가 **실제로 조작된 위치**다. `FRONT`/`MID`/`BACK`이라는 이름이
아니라 이 비율이 조건별로 분리되는지를 파일럿에서 눈으로 확인한다. 안 갈리면 지문이 짧은 것이다.

---

## 6. 통계

**주분석** — `FRONT`/`MID`/`BACK`만, `NOINSTR` 제외:
```
GEE 로지스틱  hallucination ~ C(position, Treatment(reference="BACK"))
클러스터: question_id
```
`over_abstention`에 대해 같은 모형을 한 번 더 돌린다. 환각만 보면 트레이드오프를 놓친다.

**2차분석** — 근거 위치와의 상호작용 (answerable 20문항만):
```
hallucination ~ C(position) * C(evidence_doc)
```

**사전 계획 대조** (별도 검정 가족, Bonferroni 3): `NOINSTR` vs `FRONT` / `MID` / `BACK`.
지시가 있고 없고의 차이이지 위치 효과가 아니다. 표에서 절을 나눠 보고한다.

**하지 않을 것**: 실험 A의 P0~P3 요인과 B의 위치를 하나의 모형에 넣지 않는다.
이 두 실험으로 "모든 지시 종류 × 모든 위치"의 상호작용을 검증했다고 쓰지 않는다.

## 7. 지표

실험 A와 같은 정의를 쓴다. 단 **Abstention F1은 보조지표로 강등한다** —
Y·N이 반반이면 전부 보류해도 F1 ≈ 0.67이고, 답한 것의 정확성이 반영되지 않는다.
종합 판단은 **환각률–정확도 트레이드오프 평면**으로 한다.

B에서 특히 구분해 기록할 것:
- "모르겠다"와 "질문의 잘못된 전제를 바로잡았다"를 같은 라벨로 묶지 않는다.
- **보류 표현을 쓰고 뒤에 없는 내용을 덧붙인 응답**은 보류가 아니다. 별도 라벨로 센다.

## 8. 일정 게이트 — B를 포기하는 조건

B는 **확장 실험**이다. 아래를 못 지키면 B를 버리고 A만 제출한다. 이건 실패가 아니라 계획이다.

1. 채점·저장 결함 수정 + 회귀 테스트 통과
2. 실험 A 파일럿 완료, judge 선정(κ), 보류 사전 동결
3. **실험 A 본실험 완료** ← 이 시점까지 못 오면 B 착수 안 함
4. B 문항 40개 + 개발용 5개 작성
5. B 실행 960응답

## 9. 아직 검증하지 못한 것

- **실측 처리 속도가 없다.** 960응답이 몇 시간인지 모른다. A 파일럿에서 초당 토큰을 재고 나서 채운다.
- 지문 900자에서 `FRONT`/`MID`/`BACK`의 토큰 위치가 충분히 갈리는지 **아직 확인 안 됨.**
  B 파일럿(1문항 × 4조건)에서 `instr_token_index`를 찍어보고, 안 갈리면 지문을 늘린다.
- LM Studio가 seed를 실제로 반영하는지 미확인. 실험 A와 공통 과제다.
