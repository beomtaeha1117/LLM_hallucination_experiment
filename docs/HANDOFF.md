## 연구 제목 (확정)
"한국어 답변불가 질의에서 불확실성 명시·자기검증 프롬프트의 2×2 조합이 로컬 LLM의 환각률과 과잉보류에 미치는 영향"

RISS 중복 회피 근거 4가지: ① 한국어 자체 제작 unanswerable 세트 ② 로컬/온디바이스 모델 ③ 과잉보류를 대칭 지표로 둔 trade-off ④ 길이 통제 대조군으로 "자기검증"과 "출력량 증가"를 분리.

## 확정된 실험 설계 — 다시 논의하지 말 것

**독립변인**: 프롬프트 구조 7종
- 요인설계(2×2): P0 baseline / P1 불확실성 명시 / P2 자기검증 / P3 결합
- 비교군 3종: P2L 길이통제 / P4 순수 금지("지어내지 마") / P5 few-shot(예시 3개)
- P2는 **순수 자기검증**이다. "불확실하면 제거하라"는 보류 지시를 넣지 않는다 — 넣으면 P1이 섞여 2×2가 무너진다.

**종속변인 6종**
```
Hallucination Rate / Accuracy@Answerable / Correct Abstention Rate
Over-Abstention Rate / Answer Rate / Abstention F1(종합지표)
```

**통제변인**: temperature 0.7 고정, **반복마다 seed만 1/2/3 변경**(둘 다 고정하면 3회 반복이 같은 응답이 된다), top_p 0.9, max_tokens 512, context 8192, **thinking OFF**, 단일 턴(대화 이력 없음), 질문 순서 고정, GGUF/llama.cpp 통일.

**통계**
- 주분석: GEE 로지스틱 `hallucination ~ uncertainty * verification`, 질문 ID 클러스터, P0~P3만. **상호작용항이 연구질문 3.**
- 길이 교란: 위 모형에 `completion_tokens` 공변량 추가.
- 사전 계획 대조(별도 검정 가족, Bonferroni 6): P0-P2L, P2-P2L, P0-P4, P1-P4, P0-P5, P1-P5.
- 판정 신뢰도: 블라인드 400건 인간 재판정 → Cohen's κ.

**모델** (2026-09-05 웹 확인, 전부 Apache 2.0)
- Main: Qwen3.6-35B-A3B GGUF Q4_K_M (21.2GB)
- Replication: Gemma 4 12B
- Platform: gpt-oss-20b MXFP4 (16GB에 들어가 Windows RTX 5070 Ti에서도 동일 체크포인트 실행 가능)
- Judge: 위 3종과 다른 계열 1종, 파일럿에서 κ로 선정
- 본실험 환경: Mac Studio M4 Max 36GB + LM Studio

**실행 규모**: 200문항 × 7조건 × 3반복 × 3모델 = 12,600 응답 (예상 18~35시간)

## 현재 상태

**완료**
- 프롬프트 7종 (`prompts/`)
- 코드 전부 (`src/`, `tools/`, `run_all.py`) — mock으로 12,600응답 규모 통과
- 문항 200개 작성 (`data/questions_v1_DRAFT.csv`)
- 검증 도구 (`tools/make_verify_worklist.py` → `verify/worklist.html`, `tools/apply_verification.py`)
- 문서 5종 (`docs/`)

**남은 일 (우선순위)**
1. **문항 180개 사실 검증** ← 유일한 병목. `verify/worklist.html`을 브라우저로 열어 진행
2. 맥에서 LM Studio + 모델 3종 설치, `LMStudioClient`/`LMStudioJudge` 실동작 확인 (**아직 한 번도 안 돌려봄**)
3. 파일럿 140응답 → 보류 사전 구축·동결, judge 선정(κ), 천장/바닥효과 점검
4. 본실험 → 평가 → 분석
5. 인간 검증 400건 → κ
6. 제출 직전 RISS 재검색

## 반드시 지킬 것

1. **없는 논문·모델·DOI·링크를 절대 만들어내지 말 것.** 존재하지 않는다고 표시한 논문·용어·조항이 실제로 존재하면 채점 기준이 틀린 것이 되고 감점 -2다.
2. 2026년 현재 모델·소프트웨어 정보는 반드시 웹 검색으로 확인할 것.
3. 내 아이디어가 연구적으로 약하면 동의하지 말고 비판적으로 수정할 것.
4. 독립·종속·통제변인이 섞이지 않게 할 것.
5. 환각 감소만이 아니라 정확도-보류 trade-off를 볼 것.
6. Python 자동화를 적극 활용하고, 코딩은 서브에이전트에 위임할 것.
7. **결과를 먼저 정해두지 말 것.** 결론은 실제 데이터가 나온 뒤에 쓴다.
8. `results/`와 `graphs/`에 있는 것은 **전부 mock 데이터**다. 실제 실험 전에 지울 것.
9. **보류 표현 사전은 P0·P2 응답으로 먼저 만든 뒤 P1·P3 표현을 추가**할 것. P1·P3에만 "확인할 수 없습니다"가 지정돼 있어서, 사전을 그 표현에 맞추면 조건 간 차이가 인위적으로 부풀려진다.
10. **judge와 피험 모델을 동시에 메모리에 올리지 말 것.** 36GB에 21.2GB 모델 둘은 불가. 응답 전량 생성 → 언로드 → judge 로드.
11. 채점 기준(허용오차, 부분정답)은 **데이터 수집 전에** 확정할 것. 결과를 보고 기준을 바꾸지 않는다.

## 논문·포스터 감점 조건

- 포스터: PDF, 이미지·표 4개 이상(3개 이하 -1), 서론·결론 필수
